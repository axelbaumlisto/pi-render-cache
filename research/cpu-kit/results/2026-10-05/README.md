# Сырые замеры, 2026-10-05

pi 1.0.2, Apple M3, Node 22.23.0, macOS. Каждый запуск — настоящий `pi` в
псевдотерминале 50×160 через `run.sh`, посторонние расширения из
`~/.pi/agent/settings.json` на время замера убирались. Сессии — настоящие
расшифровки с этой машины, возобновлённые через `--session`.

Выводы из этих файлов: [`../../FINDINGS.md`](../../FINDINGS.md). Отправлены в
апстрим: <https://github.com/earendil-works/pi/issues/6665#issuecomment-5986460528>

## Чем это кончилось

Расширение снято со всех семи машин: процессорное время с ним и без него
совпадает во всех трёх парах, а вся сегментация за большую сессию — 17.3 мс
против 2.5 с ЦПУ.

Настоящая цена — перерисовка всего дерева на каждый кадр при кеше, живущем один
кадр. Снаружи не чинится: прототип межкадрового кеша даёт 1.8×, но отдаёт
устаревшие строки, и сверка это поймала.

## Как повторить

```bash
cd ..            # research/cpu-kit
./run.sh scaling "$(ls -S ~/.pi/agent/sessions/*/*.jsonl | head -1)" 40 mixed
KIT_XFRAME=all ./run.sh xframe "$(ls -S ~/.pi/agent/sessions/*/*.jsonl | head -1)" 50 mixed
./collect.sh 3 45
```

Один прогон ничего не доказывает: кадровые замеры гуляют от 10 до 124 мс на
кадр. Нужна медиана нескольких прогонов либо детерминированный прогон.
